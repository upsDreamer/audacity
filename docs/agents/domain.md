# Domain Docs（领域文档）

工程技能在探索代码库时应如何使用本仓库的领域文档。

## 探索前，先阅读这些

- 仓库根目录的 **`GLOSSARY.md`**，或
- 仓库根目录的 **`GLOSSARY-MAP.md`**（如存在）：它指向各上下文各自的 `GLOSSARY.md`，阅读与主题相关的每一个。
- **`docs/adr/`**：阅读与即将工作的领域相关的 ADR。

本仓库为单上下文布局。如这些文件尚不存在，**静默继续**——不要指出其缺失，也不要建议立即创建。`/domain-modeling` 技能会在术语或决策真正确定时惰性创建它们。

## 文件结构（本仓库采用单上下文）

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用词汇表中的术语

当输出提到某个领域概念时（问题标题、重构提案、假设、测试名称），使用 `GLOSSARY.md` 中定义的术语，不要漂移到词汇表明确避免的同义词。

如果所需概念尚不在词汇表中，这是一个信号：要么是在发明项目不使用的语言（请重新考虑），要么存在真正的空白（记录下来，交给 `/domain-modeling`）。

## 标记 ADR 冲突

如果输出与现有 ADR 相矛盾，请显式指出，而不是静默覆盖：

> _与 ADR-0007 矛盾，但值得重新讨论，因为……_
